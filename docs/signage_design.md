# 街景店招汉字指数：测量说明与注意事项

## 测的是什么

每个抽样街道点在每个有影像的年份，是否能在街道两侧看到含汉字的文字框，以及汉字文字框的数量、占所有文字框的比例、占画面的面积比例。汇总到县（kabupaten/kota）× 年。

## 抽样

- 在每个行政单元内，沿 OSM 道路（primary 到 residential）每 50 米取一个候选点，再随机抽到每单元上限。随机起点保证不是总落在路口。
- `bearing` 是道路方向，取图时朝 bearing ± 90°，即面向街道两侧的店面。
- OSM 道路密度本身与发展水平相关，所以用的是"每条道路等距抽样"而不是"按 OSM 商铺节点抽样"，后者会把 OSM 覆盖差异带进去。

## 历史影像

- Static API 的 metadata 只返回最新一张全景。历史全景来自 Maps JavaScript API 返回对象里的 `time` 数组，这个字段不在 Google 的公开文档里，随时可能变。`discover_jsapi` 用无头浏览器调用它。
- 印尼的 Street View 覆盖主要从 2013 年开始，大城市更早更密，小城镇可能只有一两个年份。面板一定是不平衡的，用 `n_points_multi_year` 检查每个县有多少点能做组内比较。
- 影像拍摄时间不是你选的。同一县内不同点的年份不同，回归要用全景级的日期，不要假设整县同年。

## 识别上的威胁

1. **覆盖内生**。Google 先拍哪里、重拍哪里与商业活跃度相关。对策：只用在首期就有影像的点做面板；报告覆盖率随暴露的变化。
2. **中国籍商户 vs 印尼华人**。产业园附近的中文招牌可能是中国劳工生活区的店。对策：剔除产业园 N 公里范围做稳健性；简体/繁体比例可以部分区分（印尼老华人社群传统上用繁体）。
3. **OCR 误差**。街景文字小、有角度、有遮挡。EasyOCR 对店招级别的大字可用，对小字漏检多。误差若与暴露无关只是衰减，若中资园区的招牌更新更大更清晰则会有方向性偏差。对策：`validate-export` 分层抽 200 张人工编码，报告 precision/recall，并按高低暴露地区分别报告。
4. **日文、韩文**。Hangul 和假名不在正则范围内；日文汉字会被算入，但印尼街头极少。
5. **非店招文字**。车牌、路牌、广告牌。路牌极少用汉字；中文广告牌（房地产、电信）本身也是公开中文使用，可以保留但在稳健性里按框大小和位置剔除。

## 这个指标测的是华人还是中国人

店招上的中文混合了三种来源：印尼华人的身份展示（结果变量）、中国籍人员和中资企业的在地存在（接近处理变量）、面向中国顾客的商业策略（店主族裔不限）。不拆开，产业园附近的指标会被第二项主导，回归会机械地得到正相关。

`classify` 阶段按三类信号给每个汉字框打分：

- **字体**：繁体偏本地（老社群惯例），简体弱偏大陆（年轻华人也用简体，所以权重只有一半）。
- **关键词**：川菜、东北、兰州拉面、项目部、宿舍、青山、德龙 等偏大陆；公会、会馆、庙、宫、宗亲、印尼、中华、孔教、三语 等偏本地。词表在 `signage/classify.py` 顶部，按人工编码结果修改。
- **同图拉丁文字**：有印尼语日常词（toko、jalan、warung、yayasan）或闽客语借词（bakmi、kwetiau、cap go meh）偏本地；只有拼音没有印尼语偏大陆。

得分差 ≥ 1 判为 local，≤ −1 判为 mainland，其余 ambiguous。汇总后有 `share_points_local` 和 `share_points_mainland` 两个指数。预期如果假设成立，中资进入处 mainland 上升、local 不升或下降。

分类本身有误差，`validate-export` 的标签表里有 `human_sign_type` 列，按同一套流程报告混淆矩阵。额外的稳健性：剔除中资产业园周边若干公里；只看首期已有影像且已有汉字招牌的老华人街区；用 Dukcapil 的 WNA（外籍）人口和移民局中国籍 KITAS 数做控制。

## OCR 后端实测（合成店招图，2026-10）

在云容器里用 WenQuanYi 字体渲染了四张店招（繁体本地、简体大陆、繁体社团、无汉字），用 EasyOCR 1.7.2 实跑：

| 模型 | 繁体 金龍酒家 | 简体 东北饺子馆 |
| --- | --- | --- |
| ch_sim + en | 置信度 0.02 到 0.06，字符错乱 | 0.7 到 0.9，正确 |
| ch_tra + en | 0.99，正确 | 0.6 到 0.97，但输出被映射成繁体形 |

结论：单一模型会漏掉一半脚本。默认检测器改为 `EasyOCRDualDetector`，同一张图跑两个模型，按文字框 IoU 配对后取置信度高的读数，哪个模型赢就把它当作 script 信号。在四张合成图上 CJK 检出 4/4，local/mainland 分类 4/4。

两个附带的改动：关键词匹配前用 zhconv 把文本折成简体，词表同时列了繁体写法，这样 ch_tra 读出的 "東北餃子館" 也能命中大陆词。`--detector easyocr-sim` 和 `easyocr-tra` 保留单模型用于对比。

PaddleOCR 3.7 装上了但模型权重的下载源（百度、HuggingFace）在容器里被拦，没有实测；封装同时支持 3.x 和 2.x 的 API。本地试点时用 `scripts/ocr_smoke.py --detector paddleocr` 先跑一遍合成图再上真实街景。

合成图是干净的正面大字，真实街景有角度、遮挡、小字和反光，上面的数字只说明封装能用，不代表真实 recall。真实 precision 和 recall 必须从 `validate-export` 的人工编码里来。

## 成本

每张图按 Google 当前 Static API 价格计费，`signage cost` 按每千张 7 美元估算，用前自己核一下价格。两县试点 600 点 × 2 方向 × 平均 2 个年份约 2400 张。

## 与投资暴露的匹配
